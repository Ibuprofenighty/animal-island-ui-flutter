# Maintenance / 维护

The package version in `pubspec.yaml` is experimental. Breaking public behavior requires a minor version and migration notes; patch releases retain contracts. Public tokens, semantics, event timing and focus behavior are API. Use one implementation and update contracts, consumers, tests and documentation atomically, without compatibility shims.

CI configuration is maintained with the source. A local result does not prove hosted CI passed. Keep evidence immutable and source-bound; use unique attempt names and record launch/completion status. Re-run affected checks after source changes. Historical outputs and missing manual evidence must not be counted as current passes. The repository owner supplies issue/security reporting and support terms for external distribution.

## Physical template contracts

`library.json` and the 40 registered `components/*/contract.json` files follow UI Library Method schema 1.0. `docs/component-reference-details.json` holds reference observations and unaccepted implementation notes; it is not a second interface definition. Product-wide source identity is recorded in `docs/reference-gallery.json`. Keep added scenarios mapped to the applicable checks in `library.json`; a mapping is not a passing test or manual review.

Update the authored behavioral contract, consumers, tests, documentation and bilingual usage Skill atomically. Component input contracts link exported Dart declarations for complete signatures and defaults instead of duplicating parameter lists; verify those references when moving or removing declarations. Do not reintroduce unsupported schema fields or unregistered draft components. Use `python -B` for repository scripts to keep generated bytecode outside the declared source scope.

Run the installed UI Library Method `scripts/method.py check --project <this-repository>` with its validated local Python environment. `valid-draft` validates structure and references only. Commercial assets, visual comparison and release decisions need their actual evidence; never infer those from this status. Screen-reader coverage and other current limitations are documented in ACCEPTANCE.md.

The revoked custom-design APIs and their completed Button migration command are removed. Maintain only reference component families and their explicit support types; do not retain obsolete exports solely because old tests exercise them. Register audit findings before repair and verify all consumers after deletion.

The existing `tool/verify.py` source policy checks maintained-file coverage, contract declaration references, component export owners and reachability from both package entries and Gallery main. Conditional platform imports remain distinct adapters. These structural checks do not prove the absence of all semantic duplication or dead branches; review behavior and callback lifetimes separately.

## Performance diagnosis and proposed acceptance / 性能诊断与验收提案 (2026-10-18)

Gallery owns the two-layer dot drawing. It batches the same circles with round-cap points, preserving coordinates, diameters, layer order, paint values, contents and animation. No cache, RepaintBoundary, alternate renderer or public API was added. The previous cache experiment remains reverted. Three paired samples per target found Windows raster P95 medians22.893→4.044ms for Icon scroll and27.630→2.828ms for Carousel; Chrome7.4→5.2/5.6→4.5ms, Edge7.101→6.2/5.5→4.6ms. These are frame costs, not physical display FPS. Native dot AA differs by at most5/255 per channel; Web pixels match in8size/DPR cases. Source-bound originals, rejected zero-frame hover sample, raw traces, negative Home control and changed-load return control are retained in the performance evidence named by the single report.

Gallery仅合并自有两层圆点的绘制命令，保持坐标、直径、图层顺序、画笔色值、内容和动效；未增加缓存、RepaintBoundary、替代渲染器或公共API，之前的缓存实验仍已撤销。每端各三次对照的raster P95中位数：Windows图标滚动22.893→4.044ms、轮播27.630→2.828ms；Chrome为7.4→5.2/5.6→4.5ms，Edge为7.101→6.2/5.5→4.6ms。这是帧耗时，不是物理呈现FPS。原生圆点抗锯齿单通道最大差5/255，Web的8组尺寸/DPR像素一致。原始数据、零帧悬停无效样本、时间线、主页负向对照与负载变化后的原版返回对照均保留于唯一报告指向的性能证据。

Only the60fps direction is approved. Detailed limits below are proposals, not current PASS: AC/Balanced, record hardware/refresh/DPR/backend, no parallel builds/tests/scans;30s idle observation with proposed CPU<10%. Five process/profile repetitions,5s warmup each scene; Home30s, Icon30s with six down/up cycles, Carousel60s with original interval/motion, at least300active frames. Use validated1280×720 logical viewport/DPR1 plus375×812 Web; current diagnostic client sizes are different and recorded. For every sample propose build/raster P95≤16.667ms, P99≤33.333ms and at most1% over33.333ms; investigate every>100ms frame without trimming. Report144Hz6.944ms overruns separately. Preserve failed/paused/insufficient/confounded samples and repeat the complete pair after correcting the cause. Do not disable product motion or content. Native timestamps share engine/VM clock; Web phase markers must use performance.now()*1000, not the incompatible epoch-ms Timeline.now observed in this diagnostic. Current Web comparisons use callback delivery with100ms batching limitations. These short3-run diagnostics do not execute the proposed final protocol or certify presentation FPS.

仅60fps方向已获批准，以下细节均为提案而非当前通过：交流电/平衡模式，记录设备、刷新率、DPR和后端，不并行构建、测试或扫描；采样前观察30秒空闲负载，建议CPU低于10%。独立进程/配置各五次，每场景预热5秒，主页30秒、图标滚动30秒（六组上下滚动）、轮播60秒并保留原间隔和动效，每场景至少300个活动帧。核对1280×720逻辑视口/DPR1，另测375×812 Web；当前诊断的实际客户区尺寸另有记录。建议每次build/raster P95≤16.667ms、P99≤33.333ms，超过33.333ms占比至多1%；超过100ms逐项调查，不裁掉异常值。144Hz的6.944ms超时另报。失败、暂停、帧数不足或条件受干扰的样本原样保留，修正原因后重测完整对照，不关闭产品动效或减少内容。原生使用共同引擎/VM时钟；Web阶段标记须用performance.now()*1000，不能用本次发现不兼容的epoch毫秒Timeline.now；本次Web对比按回调送达分组，保留100ms批送限制。当前短时三轮诊断不等于已执行最终方案或证明物理FPS。

Proposed review guards: ZIP512KiB, complete Web disk60MiB, Windows disk50MiB, new-profile uncompressed localhost first-screen received bytes20MiB, local navigation→first-engine-frame2s and native process-launch→first-frame1s. These rounded engineering guards require approval and correct boundaries; Dart-main postframe is not process startup, new-profile browser cache is not OS-cold, first-engine-frame is not all-content/input readiness, and8s settled transfer is separate. Record new-profile and cached reload requests/received bytes/failures; full disk includes engine alternatives and unused assets. No production compression, WAN or hosting performance is inferred. The raw acceptance-proposal.json contains exact fields and failure policy.

建议复核护栏：ZIP512KiB、完整Web磁盘60MiB、Windows磁盘50MiB、新配置下未压缩localhost首屏接收20MiB、本地导航至首个引擎帧2秒、原生进程启动至首帧1秒。这些整数工程护栏须确认并采用正确边界；Dart-main后首帧不等于进程启动、新配置浏览器缓存不等于操作系统冷缓存、首个引擎帧不保证全部内容及输入就绪，8秒稳定窗口传输量另报。分别记录新配置和缓存重载的请求、接收量与失败；完整磁盘含引擎备选和未用素材，不推断生产压缩、广域网或托管性能。具体字段与失败处理见原始acceptance-proposal.json。
